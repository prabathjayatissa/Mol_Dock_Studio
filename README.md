# MolDock Studio

An open, original molecular visualisation, docking and drug-discovery workbench
for the desktop. MolDock Studio pairs a custom Three.js viewer with a local
Python scientific service so that structures can be imported, inspected and
(prepared for) docking entirely on your own machine — no cloud account, no
telemetry, no data leaving the computer.

> **Scientific honesty.** MolDock Studio computes *approximate* quantities. LogP,
> TPSA and friends are RDKit **calculated descriptors**, not measurements.
> Docking scores (Phase 3) are scoring-function outputs, **not** measured binding
> affinities, and never clinical evidence. Where a feature is unfinished it is
> recorded as pending in `GET /api/health` and in [`docs/roadmap.md`](docs/roadmap.md)
> rather than faked.

## Status

**Phase 0 (foundation) and Phase 1 (molecular viewer) are implemented.** The
remaining phases are planned and explicitly marked pending. The authoritative
status list is [`backend/app/core/roadmap.py`](backend/app/core/roadmap.py),
served by `/api/health` and rendered in the app's *Workflow* panel.

| Phase | Name | Status |
| ----- | ---- | ------ |
| 0 | Foundation (models, store, job layer, capabilities) | ✅ implemented |
| 1 | Molecular viewer | ✅ implemented |
| 2 | Receptor & ligand preparation | ⏳ pending |
| 3 | Molecular docking (AutoDock Vina) | ⏳ pending |
| 4 | Interaction analysis | ⏳ pending |
| 5 | Virtual screening | ⏳ pending |
| 6 | MD/AI/plugins | ⏳ pending |

### What Phase 1 actually does

- **Projects** and structure management, persisted in SQLite.
- **Import**: PDB, mmCIF, SDF/MOL, MOL2, XYZ, PDBQT, FASTA; plus **RCSB fetch**
  and **ligand generation from SMILES** (RDKit ETKDGv3 + MMFF94).
- An **original Three.js viewer**: lines, stick, ball-and-stick, space-filling,
  Cα backbone trace and a schematic **cartoon ribbon**; element/chain/secondary-
  structure/residue/hydropathy/B-factor colouring; picking, selection,
  **measurements** (distance/angle), residue labels, camera controls, PNG
  figures, viewer undo/redo.
- **Molecular surfaces** computed on the server: exact **van der Waals** (union
  of spheres) and **solvent-accessible** (Richards probe) isosurfaces, cached on
  disk and streamed as base64 typed arrays.
- **Structure export**: PDB, mmCIF, SDF/MOL, MOL2, XYZ.
- A **real background-job layer** (SQLite queue + subprocess workers, progress,
  cancellation, timeouts) exercised by a visible *self-test*.

### Explicitly pending (not hidden)

- Electrostatic-potential colouring (needs partial charges + Poisson–Boltzmann).
- **Connolly solvent-excluded surface** — Phase 1 ships vdW and SAS only.
- DSSP-accurate cartoon (helices as coils, sheets as arrows); Phase 1 draws a
  flat ribbon.
- All of phases 2–6 (preparation, docking, interactions, screening, MD/AI/plugins).
- Alembic migrations are scaffolded but autogenerated revisions are not yet
  committed; SQLite uses `create_all`.

## Quick start

### Native (fastest) — Python 3.12 + Node 20+

```bash
git clone <your-fork> moldock-studio && cd moldock-studio
cp .env.example .env

# Backend: creates backend/.venv from the pinned uv.lock
make backend-setup            # == cd backend && uv sync --extra dev

# Frontend
make frontend-setup           # == cd frontend && npm install

# See exactly which scientific tools this machine can run
make native-check             # == python -m app.cli capabilities

# Run both dev servers (backend :8000, frontend :5173)
make dev
```

Open <http://127.0.0.1:5173>. The API docs are at
<http://127.0.0.1:8000/docs>.

> **AutoDock Vina is Linux-x86-64 only on PyPI.** On Apple Silicon, docking is
> reached through Docker (`linux/amd64`) or a native Vina binary
> (`MOLDOCK_VINA_BINARY`). Everything else — parsing, descriptors, surfaces — runs
> natively. `/api/health` tells you the truth for the machine you are on.

### Docker

```bash
# Apple-Silicon-friendly: everything except Vina
docker compose up --build

# Full scientific stack including AutoDock Vina (via Rosetta on Apple Silicon)
MOLDOCK_PLATFORM=linux/amd64 MOLDOCK_INSTALL_VINA=1 docker compose up --build
```

## The five-minute tour

1. **Create a project** in the *Structures* panel.
2. Click **RCSB** and fetch `1UBQ` (ubiquitin) — the viewer loads a cartoon
   ribbon; try the *Represent* and *Colour* controls in the toolbar.
3. Fetch `3PTB` (trypsin + benzamidine). It imports as a **complex**; switch to
   *Ball & stick* to see the bound ligand, and toggle **Surface**.
4. Shift-click two atoms, press **Distance**; the measurement appears in the
   *Properties* panel and in 3D.
5. **Export → PDB**, or **PNG** for a figure.
6. In *Workflow*, press **Run self-test** to watch a real background job stream
   progress through the durable queue and subprocess worker.
7. Open the *Structures* panel's **SMILES** dialog and build a ligand such as
   `CC(=O)Oc1ccccc1C(=O)O` (aspirin) — computed descriptors appear in
   *Properties*, clearly labelled as calculated.

A scripted version of this is in [`docs/example-workflow.md`](docs/example-workflow.md).

## Architecture in one paragraph

The **frontend** (React + TypeScript + Vite + Zustand) owns only presentation and
an original Three.js engine; it never parses chemistry. The **backend**
(Python 3.12 + FastAPI) turns every import into one canonical `ParsedStructure`,
then serialises a compact column-oriented **structure packet** for the viewer and
computes surfaces on demand. Heavy work runs in **isolated subprocess jobs**. The
layers are described, with a diagram, in
[`docs/architecture.md`](docs/architecture.md).

```
frontend/  React + TS + Vite + Three.js + Zustand          (the viewer)
backend/   FastAPI + SQLAlchemy + RDKit + gemmi + SciPy     (the science)
docs/      architecture · api · dependency matrix · roadmap · validation
```

### Backend layout

| Path | Purpose |
| ---- | ------- |
| `backend/app/api/` | HTTP routes, dependency wiring, error envelope |
| `backend/app/schemas/` | Pydantic request/response models (camelCase on the wire) |
| `backend/app/services/` | Projects, structures, surfaces, store, provenance, jobs |
| `backend/app/services/io/` | Parsing, bond perception, secondary structure, packets, writers, RCSB |
| `backend/app/services/geometry/` | vdW and solvent-accessible isosurfaces |
| `backend/app/services/chemistry/` | Elements and RDKit descriptors |
| `backend/app/core/` | Config, errors, logging, security, capabilities, roadmap |
| `backend/app/db/` | SQLAlchemy models (14 tables), session, metadata |

### Frontend layout

| Path | Purpose |
| ---- | ------- |
| `frontend/src/viewer/` | The Three.js engine and its pure helpers (colouring, picking, surfaces, cartoon) |
| `frontend/src/stores/` | Zustand stores: session, structure, viewer, jobs |
| `frontend/src/components/` | Shell panels: Toolbar, Viewport, Structure, Properties, Workflow, Status |
| `frontend/src/api/` | Typed client and wire types mirroring the backend schemas |

## Testing

```bash
make test              # backend pytest + frontend vitest (and tsc)
make test-backend      # pytest only
make test-frontend     # tsc --noEmit + vitest
make test-e2e          # Playwright acceptance test (Phase 1)
make lint              # ruff (backend) + tsc (frontend)
```

The Phase 1 **acceptance test** is defined in
[`docs/scientific-validation.md`](docs/scientific-validation.md) and implemented
as backend tests (`backend/tests/test_science_validation.py`,
`backend/tests/test_api.py`) plus a browser test
(`frontend/e2e/acceptance.spec.ts`). It imports a real protein and a real
complex, checks geometry against published values, computes a surface, and
round-trips an export.

A fast, dependency-light smoke check that needs no test framework:

```bash
cd backend && .venv/bin/python scripts/preflight_checks.py
```

## Configuration

All settings come from the environment (see [`.env.example`](.env.example)):

| Variable | Default | Meaning |
| -------- | ------- | ------- |
| `MOLDOCK_ENV` | `development` | `development` or `production` |
| `MOLDOCK_LOG_LEVEL` | `INFO` | Python log level |
| `MOLDOCK_DATA_DIR` | `./data` | Runtime data root (projects, artifacts, caches) |
| `MOLDOCK_DATABASE_URL` | `sqlite:///./data/moldock.db` | SQLAlchemy URL (Postgres supported) |
| `MOLDOCK_CORS_ORIGINS` | `http://localhost:5173,...` | Allowed browser origins |
| `MOLDOCK_MAX_UPLOAD_MB` | `200` | Upload size ceiling |
| `MOLDOCK_MAX_ATOMS` | `500000` | Atoms accepted per structure |
| `MOLDOCK_VINA_BINARY` | — | Path to an external AutoDock Vina (Phase 3) |
| `MOLDOCK_SCIENTIFIC_BACKEND_MODE` | `native` | `native` or `docker` (informational) |
