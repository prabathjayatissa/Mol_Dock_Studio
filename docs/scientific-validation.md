# Scientific validation protocol

This document defines how MolDock Studio is checked against reality — and, just
as importantly, what those checks **do not** prove.

## Principle

MolDock Studio is a *tool*, not an oracle. Its validation is therefore about two
things only:

1. **Correctness of transport and parsing** — does the number that enters a file
   equal the number the user sees on screen?
2. **Correctness of the physics/chemistry we compute** — do our geometry and
   descriptor routines agree with independent reference values within stated
   tolerances?

It is **not** a claim that any score predicts binding, that any structure is
correct, or that the software is fit for a clinical or regulatory purpose.

> **A passing test means the code did what we said it does. It does not mean the
> science is validated.** Docking scores (Phase 3) are scoring-function outputs,
> not measured affinities.

## Reference data

All reference structures are redistributable RCSB PDB entries committed under
`backend/app/data/` and regenerated by `python -m app.cli fetch-test-data`:

| File | Entry | Why it is used |
| ---- | ----- | -------------- |
| `1UBQ.pdb` | Ubiquitin, 1.8 Å | A small, well-characterised single-chain protein (76 residues + 58 waters) |
| `3PTB.pdb` | β-trypsin + benzamidine | A protein–ligand **complex** with a non-covalent ligand and disulfides; the intended Phase 3 redocking benchmark |
| `1STP.pdb` | Streptavidin | A second, unrelated fold |

Ligands (`benzamidine`, `aspirin`, `caffeine`, `ethanol`, `imatinib`) are stored
as `*.sdf` generated locally by RDKit, so they can be reproduced byte-for-byte.

## What is asserted, and against what

The values below are the ones checked by
`backend/tests/test_science_validation.py`, `test_parsers.py`, `test_bonds.py`,
`test_geometry.py` and `test_ligands.py`. Tolerances are deliberately loose
enough to survive platform differences in floating point and tight enough to
catch a real regression.

### Parsing (transport correctness)

| Quantity | Expected | Tolerance |
| -------- | -------- | --------- |
| 1UBQ atom count | 660 | exact |
| 1UBQ residue count | 134 (76 amino acids + 58 waters) | exact |
| 1UBQ waters | 58 | exact |
| 1UBQ element counts | N 105, C 378, O 176, S 1 | exact |
| 1UBQ chain count | 1 | exact |
| 3PTB residues | 287 | exact |
| 3PTB waters | 62 | exact |
| 3PTB hetero residues | `{CA, BEN}` | exact |
| 3PTB calcium ions | 1 | exact |

### Geometry (physics correctness)

| Quantity | Expected | Tolerance |
| -------- | -------- | --------- |
| 1UBQ radius of gyration | 12.04 Å | 11.8 ± 0.6 Å |
| 3PTB disulfide S–S lengths | 6 bonds, 2.039–2.091 Å | within [2.0, 2.15] Å |
| 3PTB peptide C–N bonds | 222 bonds, median 1.323 Å, max 1.377 Å | within [1.28, 1.45] Å |
| Benzamidine–protein closest contact | 2.815 Å | within [2.6, 4.0] Å, and **not** a covalent bond |
| 1UBQ consecutive Cα step | ≈ 3.80 Å | ± 0.05 Å |
| Benzamidine planarity (amidine N–C–N) | planar | smallest singular value < 0.5 |

### Surfaces (numerical correctness)

A single isolated atom of radius `r` must reproduce a sphere of that radius:

| Quantity | Expected | Tolerance |
| -------- | -------- | --------- |
| vdW sphere surface area (r = 1.7 Å) | 4πr² = 36.32 Å² | rel. error < 6 % |
| vdW sphere volume | 4/3 πr³ = 20.58 Å³ | rel. error < 6 % |
| SAS sphere (probe 1.4 Å) area | 4π(r+p)² | rel. error < 6 % |

The mesh is also asserted to use **float32 positions/normals and uint32
indices**, and the grid budget test asserts that a structure too large for the
spacing is *coarsened with a warning* rather than silently truncated.

### Descriptors (chemistry correctness)

Computed with RDKit; asserted against published literature values with an
absolute tolerance.

| Molecule | Formula | MW | logP (Crippen) | HBD | HBA |
| -------- | ------- | -- | -------------- | --- | --- |
| benzene | C6H6 | 78.11 | 1.69 | 0 | 0 |
| ethanol | C2H6O | 46.07 | ≈0.00 | 1 | 1 |
| aspirin | C9H8O4 | 180.16 | 1.31 | 1 | 4 |
| caffeine | C8H10N4O2 | 194.19 | **−1.03** | 0 | 3 |
| benzamidine | C7H8N2 | 120.16 | 0.97 | 2 | 1 |
| adenosine | C10H13N5O4 | 267.24 | **−1.98** | 4 | 8 |

Two deliberate notes:

- **Caffeine logP.** RDKit's Crippen logP for caffeine is **−1.03**. The widely
  quoted XlogP3 value is −0.07. The two implementations genuinely disagree, so
  the test pins the *RDKit* value and the UI always labels logP as *computed*.
- **Hydrogen independence.** logP, TPSA and HBD are identical whether or not
  explicit hydrogens are present; `NumHAcceptors` was *not* (aspirin gave 4 with
  explicit H, 3 without). The descriptor routine therefore normalises to an
  explicit-hydrogen copy, and the test asserts HBA is stable across both
  representations.

### Round-trip (no data loss)

- A structure exported to PDB and re-imported has the same atom count and
  element counts.
- PDB `CONECT` records are emitted **before** the trailing `END`.
- SDF/MOL export **refuses** macromolecules by composition (any amino-acid or
  nucleic residue) and by size (> 2000 atoms), returning a clear error rather
  than writing an invalid SDF.

## The Phase 1 acceptance test

The end-to-end acceptance test is the union of:

1. **Backend** (`backend/tests/test_api.py::test_import_protein_and_inspect_it`
   and `test_science_validation.py`): create a project → fetch/import 1UBQ and
   3PTB → assert statistics → fetch the packet → generate a surface → export.
2. **Frontend** (`frontend/e2e/acceptance.spec.ts`, Playwright): boot both
   servers, import 1UBQ, confirm the viewport reports the correct atom count and
   the canvas renders, measure a distance, and take a screenshot.

It passes only if a real protein and a real complex travel the *whole* pipeline
and the numbers survive the trip.

## Reproducing the validation

```bash
cd backend
uv sync --extra dev
uv run python -m app.cli fetch-test-data        # (re)download the reference set
uv run python scripts/preflight_checks.py       # dependency-light smoke check
uv run pytest -q -m scientific                  # only the scientific checks
uv run pytest -q                                # everything
```

Multiply-threaded BLAS is not required; on a loaded machine set
`OMP_NUM_THREADS=1` for stable, slower-but-predictable runs.

## What this protocol does not cover

- **Docking accuracy.** Phase 3 will add redocking RMSD against 3PTB; until then
  the docking engine does not exist and is reported `not_implemented`.
- **Force-field quality.** Phase 2 will validate prepared structures; Phase 1
  computes surfaces and descriptors only.
- **Reproducibility across RDKit versions.** Descriptor values are pinned to the
  locked RDKit version; a different version may shift them, which is why the
  version is reported in every provenance record.
